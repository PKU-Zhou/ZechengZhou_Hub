NVIDIA Deep Learning Accelerator
英伟达的开源项目，旨在推动采用标准化方式设计深度学习推理加速器。

凭借模块化架构，NVDLA 具备可扩展性和高度可配置性，旨在简化集成与移植

参考：
[NVIDIA 深度学习加速器 --- NVIDIA Deep Learning Accelerator](https://nvdla.org/index.html)
[一篇回答你关于NVIDIA DLA的所有疑问 - 知乎](https://zhuanlan.zhihu.com/p/593076270)


NVDLA的实现分为两类：
- Headless：NVDLA 硬件按单元进行的管理由主系统处理器负责。
- Headed：将高频中断任务委派给与 NVDLA 子系统紧密耦合的配套**微控制器**。

从硬件层面可以分为small和large两类。
目前开源的软件代码和测试例都只是针对nv_large模式，目前已经更新为nv_full模式。

###  两种运行模式：
- 独立模式：每个功能模块都会配置其执行时间和执行内容，并完成分配给自己的任务。（内存到内存）
- 融合模式：将某些模块组装成流水线。这通过绕过内存往返来提升性能，模块之间改为通过小型 FIFO 相互通信。

### 对外连接
- **Configuration Space Bus (CSB) interface**：该接口是一种同步、低带宽、低功耗的 32 位控制总线，旨在供 CPU 访问 NVDLA 配置寄存器。
- **Interrupt interface**：中断信号
- **Data Backbone (DBB) interface**： 类似于AXI


### 组件
- #### Convolution：
卷积操作处理两组数据：一组是离线训练的“权重”（在每次推理运行之间保持不变），另一组是输入“特征”数据（随网络输入而变化）。

- #### Single Data Point Processor：
对单个数据点应用线性和非线性函数
- #### Planar Data Processor： 
maximum-pooling, minimum-pooling, and average-pooling
- #### Cross-channel Data Processor：
local response normalization (LRN)
- #### Data Reshape Engine

- #### Bridge DMA：
在系统 DRAM 与专用高性能内存接口（如果存在）之间移动数据

### 配置
- **Data types.** NVDLA 的各个功能单元原生支持多种数据类型；可以选择其中一部分以节省面积。可选数据类型包括 binary、int4、int8、int16、int32、fp16、fp32 和 fp64。
    
- **Input image memory formats.** NVDLA 可以支持平面图像、半平面图像或其他打包内存格式。这些不同模式可以启用或禁用，以节省面积。
    
- **Weight compression.** NVDLA 具备通过稀疏存储卷积权重来减少内存带宽占用的机制。可以禁用此功能以节省芯片面积。
    
- **Winograd convolution.** Winograd 算法是针对特定卷积维度的一种优化。NVDLA 可以构建为支持或不支持该算法的版本。
    
- **Batched convolution.** 批处理是一项能够节省内存带宽的功能。NVDLA 可以构建为支持或不支持该功能。
    
- **Convolution buffer size.** 卷积缓冲区由若干个存储体组成。可以调整存储体的数量（从 2 个到 32 个）以及每个存储体的大小（从 4 KiB 到 8 KiB）。（将两者相乘，即可确定实际实例化的卷积缓冲区内存总量。）
    
- **MAC array size.** 乘累加引擎以二维形式构成。宽度（“C”维度）可在 8 到 64 之间调整，深度（“K”维度）可在 4 到 64 之间调整。（所创建的乘累加单元总数可通过将这两个数相乘来确定。）
    
- **Second memory interface.** NVDLA 可以支持用于高速访问的第二存储器接口，也可以仅配备一个存储器接口。
    
- **Non-linear activation functions.** 为节省面积，可以移除支持非线性激活函数（如 sigmoid 或 tanh）的查找表。
    
- **Activation engine size.** 每个周期生成的激活输出数量可在 1 到 16 之间调整。
    
- **Bridge DMA engine.** 可以移除桥接 DMA 引擎以节省面积。
    
- **Data reshape engine.** 可以移除数据重塑引擎以节省面积。
    
- **Pooling engine presence.** 可以移除池化引擎以节省面积。
    
- **Pooling engine size.** 可以调整池化引擎，使其每个周期产生 1 至 4 个输出。
    
- **Local response normalization engine presence.** 本地响应归一化引擎可以移除以节省面积。
    
- **Local response normalization engine size.** 局部响应归一化引擎可进行调整，以实现每个周期生成 1 至 4 个输出。
    
- **Memory interface bit width.** 可以根据外部内存接口的宽度调整内存接口位宽，从而适当设置内部缓冲区的大小。
    
- **Memory read latency tolerance.** 内存延迟时间定义为从发出读取请求到返回读取数据之间的周期数。可以调整对此延迟的容忍度，这会影响每个读取 DMA 引擎内部延迟缓冲区的大小。
