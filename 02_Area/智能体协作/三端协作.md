# 三端协作

> **云端存版本，本地做开发，远端跑计算。**
>
> 状态：方案设计，尚未实施。

## 为什么这样安排

科研任务需要不同服务器上的 EDA 工具、GPU 等资源，而代码编辑、智能体协作和差异检查在本地更方便。旧服务器还可能无法运行新版 VS Code Server，因此把开发环境留在本地，通过普通 SSH 调用远端计算资源。

## 三层结构

![[Excalidraw/Drawing 2026-11-14 21.34.20.svg]]

**“三端”指三类职责，不限定为三台机器。** 从上到下分别是：

| 层级                 | 主要职责                        | 保存什么                 |
| ------------------ | --------------------------- | -------------------- |
| **① 云端：GitHub**    | 保存版本、管理分支、协作                | 已提交并推送的代码、配置和运行脚本    |
| **② 开发端：本地电脑**     | VS Code + Codex；编辑、审阅、小样例测试 | 本地 WSL2 工作区中的 Git 仓库 |
| **③ 计算端：课题组多台服务器** | 按任务提供 EDA、GPU、CPU 等计算资源     | 固定代码快照、数据、完整日志和运行产物  |

本地用 VS Code 的 WSL 扩展打开项目，让 Codex、Git 和命令行工具使用**同一份代码**。再从 WSL 通过普通 SSH 连接目标服务器，服务器无需安装 VS Code Server。

## 多台服务器怎么分工

| 服务器类型 | 主要任务 |
| --- | --- |
| **EDA 服务器** | 使用专用 EDA 工具进行综合、仿真、布局布线等任务 |
| **GPU 服务器** | 模型训练、推理及其他 GPU 加速计算 |
| **其他服务器** | CPU 计算或其他专用任务，按需要扩展 |

**按任务选择服务器，只同步本次任务需要的代码、配置和脚本。** 各服务器的工作目录、数据位置和运行环境分别记录，不要求所有服务器的软件环境相同。

## 日常怎么用

1. **本地开发**：用 Codex 修改代码，在 VS Code 中查看差异、完成小样例测试；环境相关问题到对应服务器验证。
2. **保存版本**：正式实验前提交并推送代码，从该版本生成固定代码快照。
3. **选择服务器并运行**：按任务选择 EDA、GPU 等服务器，通过 rsync over SSH 上传快照；同步成功后，用 SSH 提交任务。有调度器的集群由调度器管理长任务。
4. **查看结果并迭代**：按需回传状态、报错片段、指标和小型结果，在本地分析、继续修改。完整日志和大文件留在远端。

## 长期遵守的约定

- **本地是日常修改入口。** 服务器上的临时修复通过提交或补丁带回本地；GitHub 是同一仓库的远端，不另建“提交专用副本”。
- **正式实验可追溯。** 每次使用独立运行目录，排队和运行期间不覆盖源码；记录提交编号、目标服务器、参数、随机种子（如适用）、数据与环境版本、任务编号。未提交的修改不能只靠提交编号追溯。
- **源码与大文件分开。** 数据、日志、模型权重和运行产物不进入普通代码仓库；Git 忽略规则与同步排除规则分别配置，关键数据和结果另行备份。
- **GitHub 不作为运行的必经中转。** 默认由本地直接上传到目标服务器；GitHub 保存已提交且已推送的版本，不与每次本地编辑实时同步。
