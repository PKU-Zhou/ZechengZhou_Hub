# 三端协作实施清单

> **状态：待实施。以下均为计划，尚未执行。**
>
> 关联方案：[[三端协作]]。先用一个小项目跑通流程，再扩展到更多服务器；每阶段验收通过后再进入下一阶段。

## 阶段一 确认资源

- [ ] **本地准备**：确认 Windows 能使用 WSL2，准备 VS Code、Codex 账号和足够的磁盘空间。
- [ ] **服务器信息**：逐台记录 SSH 地址、端口、账号、VPN／跳板机需求、系统版本、工作与数据目录、磁盘配额、任务提交方式。确认 EDA 工具与许可证、GPU 资源是否可用。
- [ ] **验收**：明确试点项目、GitHub 仓库归属，以及 EDA、GPU 任务分别在哪台服务器执行。

## 阶段二 配置本地开发环境

- [ ] **准备与配置**：使用 WSL2，在其中准备 Git、SSH、rsync 和项目所需的轻量运行环境；项目放在 Linux 用户目录下，如 `~/projects/项目名`。
- [ ] **连接编辑器**：通过 VS Code 的 WSL 扩展打开项目，配置 Codex，让编辑器、智能体和终端使用同一份代码。[WSL 使用说明](https://learn.chatgpt.com/docs/windows/wsl)
- [ ] **验收**：VS Code 显示 WSL 环境；Codex 能读取项目、修改一个小文件，改动能在 diff 中查看；本地小样例测试通过。

## 阶段三 配置 GitHub 版本库

- [ ] **准备**：选定或新建项目仓库，确定归属、可见性和协作者。
- [ ] **配置**：在 WSL 设置 Git 提交身份和仓库远端；复用或生成 SSH 密钥，将公钥加入 GitHub。设置 `.gitignore`，排除数据、日志、权重、本地环境和凭据。[SSH 认证说明](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/testing-your-ssh-connection)
- [ ] **验收**：在测试分支完成一次提交和 push，再从临时目录 clone，确认文件与提交编号一致。服务器无需直接访问 GitHub。

## 阶段四 配置各台计算服务器

- [ ] **连接与目录**：在 WSL 的 `~/.ssh/config` 中分别设置 EDA、GPU 等主机别名和登录方式，配置公钥认证；确认各端都有 rsync。源码快照、运行输出与大数据分开存放。
- [ ] **运行环境**：记录每台服务器的环境加载方式、数据路径及资源申请方法；以下小任务在允许的计算节点执行。

| 服务器 | 准备与配置 | 验证通过的标准 |
| --- | --- | --- |
| **EDA** | 工具版本、许可证、工艺库／设计依赖、环境初始化脚本 | 通过 SSH 批量运行一个小型综合或仿真任务，正常结束并生成预期报告 |
| **GPU** | 确认现有驱动版本，配置兼容的框架环境及 GPU 队列或分配方式 | 获得 GPU 资源后，完成一次实际 GPU 运算或短训练，不能只确认驱动能识别设备 |
| **其他** | 对应编译器、运行库与资源配置 | 最小任务成功，输出符合预期 |

- [ ] **验收**：上述任务在非交互 SSH／作业脚本中也能加载环境，工作目录可写、数据路径可读。GPU 框架版本按服务器条件选择，可参考 [PyTorch 安装与验证](https://docs.pytorch.org/get-started/locally/)。

## 阶段五 验证代码同步

- [ ] **准备**：从干净的已提交版本生成固定快照，记录提交编号和文件校验清单；确认所需源码、配置与依赖文件齐全。
- [ ] **配置**：仅向目标服务器同步本次所需文件，单独设置 rsync 排除规则；先用 `--dry-run` 检查范围，再传到新的运行目录。输出和大数据目录不纳入同步范围。[rsync 文档](https://download.samba.org/pub/rsync/rsync.1)
- [ ] **验收**：远端文件校验结果与快照一致；未传入日志、权重或本地虚拟环境。同步完成后再提交任务，后续更新不覆盖已提交任务的目录。

## 阶段六 跑通完整科研流程

- [ ] **分别试跑**：EDA、GPU 各完成一次“本地修改 → 提交版本 → 上传快照 → 远端运行 → 读取结果”。有调度器时使用调度器；没有时采用服务器允许的后台运行方式。
- [ ] **验证任务与记录**：断开 SSH 后任务仍能继续；重连可查状态、最终退出码和产物。记录提交编号、目标服务器、任务编号、参数、随机种子（如适用）及数据／环境版本。拿到任务编号只代表提交成功，仍需确认实际运行结果。[Slurm 提交说明](https://slurm.schedmd.com/sbatch.html)
- [ ] **验证智能体协作**：让 Codex 复用已验证的命令执行一个小任务，确认其 WSL 项目与 SSH 身份正确，并能读回状态、报错片段或结果摘要；完整日志留在服务器。

通过全部验收后，再考虑把上传、提交、查状态和取摘要封装成固定脚本。
